# 本地部署大模型：下载与部署

> 本地部署 = 把模型权重下载到本机 + 用推理框架加载成服务 + 通过 API 调用。
> 顺序永远是：**先算显存 → 再选模型/量化 → 再下载 → 最后选推理框架**。顺序反了就是白下几十 GB。

---

## 一、先算硬件账（最关键的一步）

### 显存估算公式

```
权重占用 ≈ 参数量 × 每参数字节数
FP16/BF16 = 2 字节/参数；INT8 = 1；Q4 量化 ≈ 0.5
实际占用 = 权重 + KV Cache（随上下文长度线性增长）+ 框架开销
```

### 常见规模对照

| 模型规模 | FP16 权重 | Q4_K_M 权重 | 舒适显存 | 说明 |
| -------- | --------- | ----------- | -------- | ---- |
| 1.5B~3B   | ~3-6 GB   | ~1-2 GB     | 6-8 GB   | 核显/轻薄本可跑 |
| 7B~8B     | ~15 GB    | ~5 GB       | 8-12 GB  | 主流入门，RTX 3060 12G 可跑 Q4 |
| 14B       | ~28 GB    | ~9 GB       | 16-24 GB | RTX 4090 24G 可跑 FP16 |
| 32B       | ~64 GB    | ~20 GB      | 24-48 GB | 4090 只能 Q4 |
| 70B       | ~140 GB   | ~40 GB      | 多卡 48G×2 | 家用基本不考虑 |
| 100B+     | -         | -           | 多卡 A100/H100 | MoE 模型可打折，但仍需大显存 |

- 内存 ≥ 显存（CPU offload 时内存要能装下剩余权重）
- 磁盘预留：下载 1 份 + 转换/量化再 1 份，建议留 **2 倍空间**
- 无独显：llama.cpp / Ollama CPU 模式可用，8B Q4 大约 **2-5 token/s**，能用但慢
- 上下文（num_ctx / max-model-len）开太大，KV Cache 会吃掉几个 GB，先设 4096 试

## 二、选模型与格式

### 常用开源模型（中文/Agent 友好）

| 模型 | 特点 | 推荐场景 |
| ---- | ---- | -------- |
| Qwen2.5 / Qwen3（7B/8B/14B/32B） | 中文强、工具调用完善 | 本地通用首选 |
| GLM-4 / ChatGLM | 中文对话好 | 中文问答 |
| DeepSeek-V3 / R1（671B MoE） | 能力最强但巨大 | 需多卡，家用不现实 |
| Llama 3.1 / 3.2 | 生态最全 | 英文、LlamaIndex 生态 |
| InternLM / Yi | 中文可替代 | 备用 |

### 权重格式怎么选

| 格式 | 用到哪 | 特点 |
| ---- | ------ | ---- |
| `safetensors` | vLLM / Transformers | 原始精度，占空间大，质量最好 |
| `GGUF` | llama.cpp / Ollama / LM Studio | 已量化，单文件，CPU/混合推理友好 |
| `AWQ` / `GPTQ` | vLLM（GPU） | 4bit GPU 量化，显存省、速度快 |
| `MLX` | Apple Silicon | Mac 专用 |

量化档位：**Q4_K_M 性价比最高**；Q5_K_M / Q8_0 质量更高；Q2/Q3 明显掉智商，不建议。

## 三、下载（国内网络环境）

### 方式 A：ModelScope（国内首选，不用梯子）

```powershell
pip install modelscope
modelscope download --model Qwen/Qwen3-8B --local_dir D:\models\Qwen3-8B
```

只下 GGUF 单文件时可直接指定文件：

```powershell
modelscope download --model Qwen/Qwen2.5-7B-Instruct-GGUF qwen2.5-7b-instruct-q4_k_m.gguf --local_dir D:\models
```

### 方式 B：Hugging Face CLI + 国内镜像

```powershell
pip install -U huggingface_hub
$env:HF_ENDPOINT = "https://hf-mirror.com"        # 当前会话生效，可写进系统环境变量
hf download Qwen/Qwen3-8B --local-dir D:\models\Qwen3-8B
```

断点续传默认支持；下载中断重跑同一命令即可。

### 方式 C：Ollama 直接拉（最省事）

```powershell
ollama pull qwen3:8b
```

### 缓存目录（避免 C 盘爆）

```powershell
# 写进用户环境变量，永久生效
setx HF_HOME D:\cache\huggingface
setx MODELSCOPE_CACHE D:\cache\modelscope
setx OLLAMA_MODELS D:\cache\ollama
```

> 注意：`setx` 设置后要**新开终端**才生效。Ollama 的模型目录修改后需要重启服务。

## 四、部署（按硬件/需求选框架）

### 1. Ollama —— Windows 最省事（推荐先跑通这个）

```powershell
winget install Ollama.Ollama     # 或官网下安装包
ollama run qwen3:8b              # 自动下载 + 启动交互
```

- 服务地址：`http://localhost:11434`，OpenAI 兼容端点为 `/v1`
- 自定义参数用 Modelfile：

```
FROM qwen3:8b
PARAMETER num_ctx 8192
PARAMETER temperature 0.7
SYSTEM 你是一个严谨的中文助手。
```

```powershell
ollama create my-qwen -f Modelfile
ollama run my-qwen
```

- 常用环境变量：`OLLAMA_NUM_GPU`（GPU 层数）、`OLLAMA_KEEP_ALIVE`（模型驻留时间）、`OLLAMA_HOST`（改监听地址）

### 2. LM Studio —— 纯图形界面，适合试玩

下载安装后在内置搜索里下 GGUF，点“加载模型”即可，自带本地 OpenAI 兼容服务器（默认 1234 端口）。

### 3. llama.cpp —— GGUF + 细粒度控制（CPU/混合推理）

```powershell
# 下载 release 里的 llama-server.exe 或自行编译
llama-server -m D:\models\qwen2.5-7b-q4_k_m.gguf -ngl 99 -c 4096 --port 8080
```

- `-ngl 99`：尽量把所有层放到 GPU；显存不足就往下调
- 端点：`http://localhost:8080/v1/chat/completions`

### 4. vLLM —— GPU 生产级，吞吐最高

限制：**不支持 Windows 原生**，需 WSL2 或 Linux/Docker，且需要 NVIDIA 显卡（CUDA）。

```bash
pip install vllm
vllm serve Qwen/Qwen3-8B --port 8000 --api-key local-key \
  --gpu-memory-utilization 0.9 --max-model-len 8192
```

```bash
# 多卡张量并行
vllm serve Qwen/Qwen3-32B --tensor-parallel-size 2 --port 8000
```

- 自动提供 OpenAI 兼容 API：`http://localhost:8000/v1`
- 适合：并发请求、做 Agent 后端、批量推理

### 5. Docker 方式

```powershell
docker run -d --gpus all -p 8000:8000 --ipc=host `
  vllm/vllm-openai:latest Qwen/Qwen3-8B --max-model-len 8192

docker run -d -p 11434:11434 -v ollama:/root/.ollama ollama/ollama
```

### 6. SGLang（可选）

DeepSeek / 高并发场景性能好，用法与 vLLM 接近：`python -m sglang.launch_server --model-path ...`

## 五、验证服务可用

```powershell
curl http://localhost:11434/v1/models
```

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
resp = client.chat.completions.create(
    model="qwen3:8b",
    messages=[{"role": "user", "content": "用一句话解释什么是 Agent"}],
)
print(resp.choices[0].message.content)
```

- 只要框架暴露 OpenAI 兼容接口，**Open WebUI / Dify / LangChain / CrewAI / 自己写的 Agent 都能直接接**
- 图形化前端：Open WebUI（`docker run` 一键起，连 Ollama 或 vLLM）

## 六、常见坑

| 现象 | 原因 / 处理 |
| ---- | ----------- |
| 下载极慢 / 失败 | 换 ModelScope 或设 `HF_ENDPOINT=https://hf-mirror.com`；hf 大文件建议开 `hf_transfer` |
| 显存 OOM | 换 Q4 量化、降低 `num_ctx`、调低 `-ngl` 或 `--gpu-memory-utilization` |
| 生成很慢 | 检查是否真的用了 GPU（`nvidia-smi`）、GPU 层数是否拉满、上下文是否过大 |
| C 盘爆满 | 改 `HF_HOME` / `OLLAMA_MODELS`，并迁移已有模型目录 |
| Windows 上跑 vLLM 报错 | vLLM 不支持原生 Windows，用 WSL2 / Docker / Linux |
| 端口冲突 | 换端口或查占用：`netstat -ano \| findstr :8000` |
| 服务暴露到公网 | 必须加 `--api-key`、防火墙只放内网、别直接映射公网端口 |
| 模型答非所问 | 检查是否用了 base 模型（应选 Instruct/Chat 版本）、模板/`chat_template` 是否匹配 |

## 七、选型速查

| 你的情况 | 推荐做法 |
| -------- | -------- |
| 只想快速跑起来 | Ollama + `qwen3:8b`（自动下载） |
| 显存 8-12G | Ollama / llama.cpp + Q4_K_M 的 8B 模型 |
| 单卡 24G（4090） | vLLM + 8B FP16，或 Ollama + 14B Q4 |
| 多卡 / 要并发 | vLLM（`--tensor-parallel-size`） |
| 没独显 / Mac | llama.cpp CPU / Ollama；Mac 可试 MLX |
| 做 Agent 后端 | vLLM（Linux/WSL2）+ OpenAI 兼容接口 |
| 完全不想碰命令行 | LM Studio / Open WebUI |

## 八、从魔塔导入 GGUF 到 Ollama（实例：Xiaomi-OCR-0）

核心认知：`OLLAMA_MODELS` 是 `blobs/` + `manifests/` 的内容寻址仓库，手动拷文件不会被识别；只能 `ollama pull` 或 `ollama create` 导入。视觉模型必须同时下载主权重和 mmproj 投影器。

| 来源 | 档位 | 体积 | 投影器 | 用法 |
| ---- | ---- | ---- | ------ | ---- |
| `richardyoung/xiaomi-ocr-0` | Q4_K_M/Q5_K_M/Q6_K/Q8_0，`latest`=Q8_0 | 747MB~1.0GB | 自带 | `ollama pull` |
| `longwayxu/xiaomi-ocr-0:bf16` | BF16 | 1.8GB | 自带 | `ollama pull` |
| 魔塔 `prithivMLmods/Xiaomi-OCR-0-GGUF` | BF16、Q3~Q6 + mmproj | 466MB~1.52GB + 207MB | 需 Modelfile 两个 `FROM` | `ollama create` |
| 魔塔 `xiaomi-research/Xiaomi-OCR-0` | safetensors 1.7GB | - | - | Ollama 不支持，用 Transformers |

本机已导入 `xiaomi-ocr:q4`（736MB，Q4_K_M + mmproj，源文件在 `D:\dev_soft\models\Xiaomi-OCR-0`）：

```powershell
ollama run xiaomi-ocr:q4 "Extract the text in the image. D:\pics\demo.png"
```
